# Progress / Roadmap

Where the port stands. STATUS.md has the full history of how each piece was
found and fixed.

The goal is the original game, running natively: fixes are limited to what
the PC port needs (timing, rendering and runtime differences from the N64),
and leave the game's own behaviour, look and balance alone.

## Done

- **ROM layout**: a resident segment plus two overlays (frontend and match)
  that load at the same address, and seven small modules the frontend
  loads after them (STATUS.md rounds 1 and 4).
- **Recompilation**: all 4232 functions recompile with no errors or
  warnings (`WASyms/wa.us.syms.toml`, generated by `tools/regen_syms.sh`).
  libultra is named from signatures; the overlays share addresses and are
  told apart by section.
- **Widescreen**: the level fills wide windows, with the landscape and
  sprites in step (STATUS.md rounds 7, 8, 10 and 11), up to 32:9, with the HUD
  anchored to the edges per the HUD Ratio setting (round 15).
- **Graphics**: the game draws with S2DEX2 (2D sprites); RT64 needed
  object rectangles added (`lib-patches/rt64/0024`, STATUS.md round 6).
- **Audio microcode**: n_aspMain, the same build btgarecomp uses,
  recompiled from the ROM (`n_aspMain.us.toml`).
- **Frontend** from btgarecomp: launcher, settings tabs, remappable
  controls, mouse stick, local multiplayer, screen filters, bloom,
  frame generation, mods tab, Add to Steam, crash reports, packaging.
- **Builds on Linux** (Ubuntu 24.04, clang 18).
- **Boots, goes through the menus and plays a match**, worms and all (single-player quick
  match, Linux with software Vulkan; STATUS.md rounds 2-5).

- **Saves**: the cartridge EEPROM (4 Kbit) saves and loads (owner, Windows).

## Next

- Play testing: whole matches, other modes.
- Steam Deck: the Linux build (`tools/package-linux.sh`) once it runs.
- Android: see `android/PLAN.md`; the match's coroutines need an aarch64
  context switch there (`src/game/coroutines.cpp`).

## Not planned yet

- Netplay and other big additions from btgarecomp.

## Where things are

| Path | What |
|---|---|
| `wa.us.toml` | N64Recomp config: hooks and fixes for the game's code |
| `WASyms/` | Symbol file (function boundaries for boot and both overlays) |
| `n_aspMain.us.toml` | RSP audio microcode config |
| `src/main/` | Frontend: window, audio, input, config, crash reporting |
| `src/game/` | Game-specific fixes called from hooks |
| `patches/` | Whole-function replacements compiled for MIPS (none yet) |
| `assets/` | UI font, icons and their licenses |
| `icons/` | App icon (`tools/make_app_icon.py`) |
| `lib/` | Submodules (runtime, frontend, RT64) and vendored libraries |
| `lib-patches/` | Patches applied to submodules at configure time |
| `tools/` | Symbol-file generation, ROM tools and release packaging |
